Agents save your secrets in a settings file

Apiiro reports that real secrets sit in public Claude Code settings files, and two common scanners missed many of them.

Apiiro, a security company, published new research on 5 November 2026. It reports that real secrets sit in public GitHub repositories, in files that AI coding agents wrote. This brief covers one finding. The window since 5 November was quiet. We could not open the Apiiro page. The figures come from a secondary report by FourWeekMBA dated 7 November 2026. Treat them as direction, not as verified data.

What Apiiro reports

Apiiro researchers Shmulik Cohen and Matan Giladi scanned public GitHub. They found 2,539 distinct real secrets in 1,994 public repositories. A secret is a key, password or token that gives access to a system. The files were written by AI coding agents.

The main file was .claude/settings.local.json. Claude Code writes this local settings file. Apiiro counted 104,185 public copies of it. Of these, 1,122 held a real secret. That is about 1.1%. The 1,122 files held 1,379 distinct secrets: 636 provider keys and 743 passwords or tokens.

How the secret gets in

An agent asks for permission to run a command. The developer approves it and chooses to allow it again later. The agent then saves the full command in a local allowlist. If the command held a secret, the file now holds the secret. Later, the developer commits the file to a public repository.

This is the cause as we understand it from the secondary report. We could not check the cause on the Apiiro page.

Scanners missed many files

Apiiro reports that TruffleHog flagged 643 of the 1,122 files. The tool gitleaks flagged 564. Neither tool flagged 215 files. Apiiro also reports 63 organizations with a real secret in a public allowlist, and 43 SSH credentials for public servers. FourWeekMBA calculated two more figures: 19.2% of files missed by both scanners, and a Claude co-authored commit in 48.8% of 1,105 traced repositories. Apiiro does not state these two figures.

What it means for the River.io Software Factory

The agent did not break a rule. It saved a command. The rule that blocks the commit was missing. We take four actions.

  1. Add local agent settings files to .gitignore in every repository.
  2. Add a pre-commit check that fails when an agent settings file is staged.
  3. Never put a secret on a command line that an agent can save. Use environment variables that the agent cannot read.
  4. Do not trust one scanner. Add a small pattern check of our own. This keeps the factory free of third-party dependencies.

CareTime, TimeForCare and MaterialsAndPractices handle regulated data. They stay at human-gated autonomy. A leaked key in those repositories is a reportable incident. Test any autonomous loop on MeowPassword, weathergalactic or sloth first.

Not featured

The Claude Code and Gemini CLI vulnerabilities (CVE-2026-54316 and CVE-2026-12537) were disclosed at Black Hat on 5 August 2026. We covered that topic on 10 August. They are not new. Daily AI digests for 7 November list products, not dark factory findings.
