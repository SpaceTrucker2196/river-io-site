What 933,000 agent pull requests reveal about autonomous coding

The first large-scale empirical studies of agent-authored pull requests put real numbers on autonomous coding, including a rejection rate roughly four times the human baseline and tests that pass without proving anything.

In early July 2026, the honest empirical evidence on autonomous coding finally showed up, and it complicates the hype. A cluster of new arXiv studies mining the AIDev dataset, roughly 933,000 agentic pull requests from Codex, Copilot, Devin, Cursor, and Claude Code across 61,000 repositories, put real numbers on agent behavior for the first time. The picture is sobering. Agent PRs get rejected far more often than human PRs (one benchmark set cites about 67 percent rejection for AI-generated PRs against about 16 percent for manual work), agent-authored tests are frequently present but of questionable quality, and test-containing PRs are bigger and slower without clearly higher merge rates. The method is real and improving, but the newest primary-source evidence says agent output still needs a hard, executable gate.

Researchers are now supplying the evidence, not vendors

The vocabulary around autonomous software production is consolidating. The "Agentic SDLC" and "AI Software Factory" are now pitched as industrialization: standardized processes, an orchestrator agent, and "bolts" (compressed delivery units where weeks become days) replacing two-week sprints. Treat the industrial-scale language as aspiration; the sources pitching it are consulting and marketing pages. The phrase that keeps recurring in more careful work, including PwC's 2026 analysis, is bounded autonomy: agents operating inside human-governed approval structures rather than exercising independent control. That is the honest description of what is actually shipping.

The substantive shift is who holds the data. The AIDev corpus is being mined in parallel by several research groups, and the descriptive findings are the most trustworthy signal the field has had. The AIDev-pop subset (33,596 PRs from repositories with more than 100 stars) is the cleaner sample: test-containing PRs are more common over time but larger and slower to land, with broadly similar merge rates. Companion studies analyze why agentic PRs merge or get rejected, and the security properties of agentic PRs at scale.

Smoke without alarms

The most important new finding of the cycle is the "All Smoke, No Alarm" study on oracle signals in agent-authored test code (arXiv 2606.18168): agents often produce tests that run but assert little of substance. Weak or missing oracles mean an autonomous loop that generates its own tests can manufacture green checks with no real verification behind them. That is the failure mode a dark factory is most exposed to, because the test suite is the gate.

An agent writing both the code and its own toothless test is a closed loop with no oracle.

The mitigation is test-driven development done properly: the human or the specification writes the failing assertion that defines correct, and the agent codes to it. Anthropic's 2026 Agentic Coding Trends Report frames the same constraint from the other side. Its "delegation gap" finding (developers use AI in about 60 percent of work but can fully delegate only 0 to 20 percent of tasks) comes with a one-line thesis: the bottleneck is no longer writing code, it is clarity about what to build. The report also finds teams with well-maintained context files see 40 percent fewer errors and 55 percent faster completion, which reconciles with earlier evidence that bloated context files hurt: lean and load-bearing, not comprehensive.

Tooling: Spec Kit v0.12.3

GitHub Spec Kit shipped v0.12.3 on 1 July 2026, adding a label-driven bug-test workflow and a warning ahead of its skills default rollout. The core loop is unchanged: Spec, Plan, Tasks, Implement, with a read-only analyze gate that cross-checks the constitution, spec, plan, and tasks for ambiguities, coverage gaps, and contradictions before any code is written. The new label-driven feature matters for issue-driven shops: it ties a reproduction test to a labeled issue, turning a bug report into a failing test first. The community ecosystem of more than 70 extensions (Jira, Azure DevOps, GitHub Issues integrations, plus security, testing, and drift gates) continues to grow, and spec templates can still be restructured to require regulatory traceability with non-optional test-first and security-review gates.

The live risks

The dependency supply chain is the open wound. The LiteLLM PyPI backdoor sat live for about three hours in March 2026 and collected roughly 47,000 downloads, and LiteLLM is the LLM gateway under CrewAI, DSPy, Microsoft GraphRAG, and dozens of agent frameworks. A single compromised transitive dependency in an agent stack is a supply-chain event with blast radius across every downstream framework.

Prompt injection remains unsolved and is accelerating. OWASP data puts growth at roughly 340 percent year over year, and it maps to six of the ten categories in OWASP's Top 10 for Agentic Applications. An OWASP researcher flatly calls it unsolved.

Agent frameworks are turning prompts into shells. Microsoft disclosed prompt-injection-to-RCE paths in agent frameworks, where a single prompt launches a process on the host. CVE-2026-22708 against Cursor lets an attacker poison the agent's execution environment so that allowlisted commands as innocuous as git branch deliver arbitrary payloads. Allowlists are not a safe boundary if the environment can be poisoned.

THE OPERATIONAL READING

With AI pull requests rejected at multiples of the human rate, the review gate is the product. Throughput claims mean nothing without the merge-quality denominator, and a green check means nothing without a real oracle behind it.

How we apply this at River.io

Our posture is native compiled code, zero third-party dependencies, test-driven development, and a GitHub-issue-driven SDLC. This cycle's evidence, as opposed to its marketing, points the same way.

The LiteLLM backdoor is the case for zero dependencies. It is a concrete, recent example of exactly the risk the rule eliminates: a transitive dependency compromise cascading through every framework that trusted it. Agentic development does not change that calculus; it sharpens it. We keep the rule, and we keep the agent toolchain itself lean.

TDD is the antidote to smoke-without-alarm tests. The research says agent-written tests often lack real oracles. Our discipline of a human-defined or spec-defined failing assertion first is precisely the control that closes the gap. On any repository where an agent may open pull requests, the agent is not permitted to author both the assertion and the implementation for the same behavior. The oracle originates from the issue or the spec, never from the coder.

The label-driven bug-test workflow maps onto our issue-driven SDLC. A labeled bug issue, a generated reproduction test, a failing test, then a fix is a clean, low-risk pattern. It keeps the human at the point that matters (defining the failing test) while the agent does the mechanical work.

Regulated work stays human-gated. Our CareTime and TimeForCare Medicaid EVV applications and our MaterialsAndPractices organic-farm compliance application run at human-gated autonomy: agents may draft, a human approves every merge, and no agent authors the compliance-defining assertions. This cycle's rejection-rate and prompt-injection data reinforce that regulated code is not the place to test lights-out operation.

Experiments run on the low-stakes repositories, with our own measurements. MeowPassword, weathergalactic, and sloth remain the sandboxes for a planner-generator-evaluator loop with an executable merge gate. The current experiment: measure how many agent PRs pass a human-authored test oracle versus an agent-authored one, giving us a local version of the AIDev merge-quality numbers rather than a citation.
