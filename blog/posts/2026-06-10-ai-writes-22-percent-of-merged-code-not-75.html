AI writes 22 percent of merged code, not 75

DX's data across 135,000 developers punctures the vendor headlines, Forrester names a new security operating model for agentic development, Salesforce posts the strongest first-party numbers yet, and a cross-vendor prompt injection shows the pipeline itself is now the attack surface.

In June 2026 the conversation around autonomous software development moved from "can agents write the code" to "who governs the pipeline." Forrester formally named the phase with its report The State of Agentic Software Development, 2026, and paired it with a new security operating model whose least mature capability is, tellingly, agent-aware quality gates. Salesforce published the cleanest first-party proof of an organization-wide agentic shift. And the most useful reality check of the season came from DX: across more than 135,000 developers, AI-authored code holds at about 22 percent of merged code, an order of magnitude below the "75 percent" and "100 percent" headlines. The throughline for any autonomous pipeline: the bottleneck is now the gate, not the generator.

Forrester names the phase, and a paradox

Forrester's framing is blunt: TuringBots are becoming agentic, not assistants embedded in one tool. Agents now span analysis and planning, design, build, test, and delivery, and are increasingly orchestrated together. You delegate intent ("build this feature") and agents decompose, generate, test, and stage the release.

The sharpest finding is a productivity paradox. Coding alone may improve 30 to 40 percent, but if planning, testing, and release stay manual, whole-team productivity often rises less than 10 percent. The lights-out win is gated by the un-automated stages, not the coding stage. Forrester's prescription: treat agents as first-class participants in a redesigned, collapsed SDLC, with humans firmly in control.

The gate becomes its own product category

Forrester analyst Janet Worthington introduced Agentic Development Security (ADS) after RSAC 2026 as "a new security paradigm protecting AI-powered software development end to end," spanning prevention, detection, prioritization, and remediation, and treating security as autonomous, policy-driven actions rather than alerts. Forrester enumerates eight capability clusters; as of RSAC, no single vendor covers all eight. The two least mature are supply-chain defense against AI-specific vectors (slopsquatting, hallucinated dependencies) and agent-aware quality gates. AI-augmented code analysis is the most mature. The read: the verification layer a dark factory most needs is the one the market is worst at, so teams have to build it themselves.

The crystallizing consensus (Codacy, CodeScene, TFiR) names three properties a verification layer must have: independence (a different system than the one that wrote the code), deterministic pass/fail for security and policy, and context awareness to verify intent. Multi-agent validation chains are now a named pattern: one agent writes, a second critiques, a third tests, a fourth checks compliance and architecture, each communicating through files. The spec-driven command surface (constitution, specify, plan, tasks, analyze, implement, checklist) is stable across GitHub Spec Kit and its clones; nothing structurally changed this cycle, which is itself a signal that the front-end spec layer has settled.

Evaluate trajectories, not just outputs

The maturing guidance pushes evaluation upstream of the answer. Score tool-choice correctness, argument validity, step count, time and cost, and policy compliance across the whole run, not just whether the final diff passes tests. A loop that only checks the end state cannot catch an agent that did the right thing the wrong, unsafe way. Policy-as-code, approvals for irreversible actions, and prompt-injection defense are now cited together as the irreducible guardrail set.

Notably, human approval checkpoints stay in the loop by design even at the aggressive end of the market. Anthropic's Claude Code "auto mode," covered by InfoQ in May 2026, is explicitly autonomous execution with layered gates: input filtering, action evaluation, two-stage classification, and human approval for sensitive operations. Even the most aggressive vendor autonomy ships with a human gate on destructive verbs. That is the reference design, not a compromise.

Salesforce's "How Engineering Became Agentic" is the strongest named-company, first-party dataset since Spotify's Honk: after an organization-wide pivot to Claude Code as the primary agent with token limits removed, the numbers above arrived with fewer incidents, not more. The Effective Output metric is Salesforce-defined, but the direction is unambiguous.

DX's Q4 Impact Report is the number to quote back at the "75 percent" and "100 percent AI-written" claims. Across more than 135,000 developers at 425 organizations, the real merged share is about a quarter (daily users about 24 percent, monthly about 20 percent), and the productivity translation is modest unless usage is daily. Google's own trajectory (about 25 percent in October 2024, about 50 percent in October 2025, 75 percent in April 2026) is consistently framed by Pichai as AI-suggested and human-accepted or edited, not autonomous shipping. The gap between Google's "75 percent suggested" and DX's "22 percent merged" is the delegation gap, quantified. Microsoft's baseline holds at about 30 percent, with 84 percent of developers using or planning to use AI and 51 percent using it daily.

The pipeline itself is the attack surface

"Comment and Control," a cross-vendor prompt injection disclosed in April 2026 and escalating since. Researchers working with Johns Hopkins put a malicious instruction in a GitHub pull request title and watched Anthropic's Claude Code Security Review action post its own API key as a comment. The same injection worked against Google's Gemini CLI Action and GitHub Copilot Agent, the first cross-vendor demonstration. The root cause is structural: these actions run untrusted input, powerful tools (bash, git push, API calls), and secrets in the same runtime. Anthropic's own system card had already conceded the action is "not hardened against prompt injection."

Microsoft Security followed up on June 5, 2026 with "Securing CI/CD in an agentic world," a Claude Code GitHub Action case study on isolating agent runtimes in CI/CD, the direct successor to May's "When prompts become shells" disclosure (Semantic Kernel CVE-2026-25592 and CVE-2026-26030). The lesson compounds: an agent in your pipeline that can read PR text and hold deploy credentials is a confused deputy by construction.

Supply chain is the bigger iceberg. Cisco AI Defense found 26 percent of roughly 31,000 agent "skills" carried at least one vulnerability, and a one-click remote code execution (CVE-2026-25253, CVSS 8.8) executed from a single malicious webpage in milliseconds. Forrester's ADS data cites security-flaw rates from about 12 percent of AI-attributed files to more than 40 percent of AI-generated tasks for specific vulnerability classes. AI security in 2026 is a supply-chain problem first and a prompt-injection problem second.

If an agent can both read a pull request comment and push to production, you have already built the vulnerability.

The design implications are consistent: least-privilege tool scoping, deterministic guards on irreversible verbs (delete, force-push, deploy, send), per-action audit logs, and runtime isolation between untrusted input and secret-holding agents.

How we apply this at River.io

River.io builds native compiled software with zero third-party dependencies, test-driven development, and a GitHub-issue-driven SDLC, with regulated products (CareTime and TimeForCare on Medicaid electronic visit verification, MaterialsAndPractices on organic-farm compliance) leading the portfolio.

The less-than-10-percent paradox is our sequencing guide. Forrester's finding says automating coding alone barely moves the needle. The highest-leverage automation is not "let the agent write more code"; it is automating the issue, spec, test, and PR stages around existing TDD so the whole loop closes. Our tests are already the deterministic gate the rest of the industry is scrambling to build.

We satisfy the ADS independence rule by construction. The hardest, least mature ADS capability is an agent-aware quality gate that is independent of the builder. Our native test suites plus a deterministic CI verifier are exactly that: a different system than the generating model. We treat that as the moat rather than replacing it with a model-based reviewer that shares the builder's blind spots.

"Comment and Control" is the threat model for any issue-driven pipeline, including ours. Our SDLC runs through GitHub issues and pull requests, which is exactly the untrusted-input surface that leaked secrets across all three major vendors. Concretely: any agent acting on issue or PR text in the regulated repositories runs with no deploy credentials, no PHI-scoped tokens, and no generic shell in the same runtime. The agent that reads issues is kept strictly separate from anything that can push, deploy, or touch a database.

Regulated repositories stay human-gated. Database migrations, PHI exports, log purges, and production deploys on the EVV apps are typed, allow-listed, human-approved tool calls, following the same pattern as Claude Code auto mode: autonomous execution, human gate on destructive verbs.

Autonomous loops run first on low-stakes repositories. On repositories with no PHI and no regulatory surface (MeowPassword, weathergalactic, sloth) we run multi-agent validation chains (writer, critic, test-runner, constitution-checker, all communicating through version-controlled files), scoped to a single task type and measured at the trajectory level, not just the final diff.

We plan around 22 percent, not 75. Realistic merged AI-authored share at well-run shops is about a quarter. We plan the factory's economics around steadily widening that number on safe repositories, not around a lights-out fantasy the data does not yet support.
